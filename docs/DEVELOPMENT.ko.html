.NET 10 SDK는 global.json으로 기준 버전을 지정합니다. win-x64 self-contained 앱과 서비스에 런타임을 포함합니다. LibreHardwareMonitorLib 0.9.6은 비공개 PawnIO 리소스 로더를 reflection으로 사용하므로 라이브러리 변경 시 호환 검증이 필요합니다.

기기와 권한

EC 접근은 제조사 GPD, 모델 G1628-04/G1628-04-L, BIOS 문자열 정확히 2.11에 한정합니다. DevicePolicy를 생성자·서비스·진단·복구·watchdog 모두에 적용합니다. 미지원 BIOS는 RPM 조회를 포함해 EC 접근을 하지 않습니다. G1628-04-L 실물 검증은 하지 않았습니다.

PawnIO의 LPC slot 1, 0x0478/0x0479 high-low-high RPM 읽기, 0x047A 출력 레지스터를 사용합니다. 자동값 0, 수동값은 roundAwayFromZero(percent × 243 / 100)+1입니다. 모든 출력 쓰기는 읽기 검증을 수행합니다. CLI의 임의 레지스터 접근은 제공하지 않습니다. EC 프로토콜 출처는 THIRD-PARTY-NOTICES.md에 보존합니다.

UI는 requireAdministrator, 서비스는 LocalSystem입니다. 설치·설정 경로 ACL을 제한합니다. 일반 권한 UI는 사용자별 권한 위임 설계가 필요하여 이번 변경에 포함하지 않습니다. Global\PocketQuiet.Hardware mutex는 Pocket Quiet 프로세스 사이만 배타 제어합니다. 알려진 외부 도구 이름 탐지와 출력 검증이 모든 외부 쓰기를 차단하지는 않습니다.

제어 정책

  • 온도 finite 5~115°C, 샘플 나이 최대 3초, 미래 최대 1초, 이전보다 증가하는 시각. RPM 0~12000.
  • EMA 시정수 4초. 적응형은 EMA + clamp(3×dT/dt,0,8) + preference×5, preference [-1,1].
  • 곡선 선형 보간. 최소 출력 30%, 상승 최대 12%p/s, 감속 조건 20초 후 최대 1.5%p/s.
  • 감속 시작은 3%p 차이를 사용하지만 시작한 감속은 목표까지 이어갑니다. 30% 최저 목표는 작은 차이에서도 도달합니다.
  • 초기 출력 상태는 60%입니다. 펌웨어에서 수동 모드로 전환할 때 최근 유효 측정이 55°C 이하이고 팬이 회전 중이면 해당 곡선의 저온 출력으로 시작해 불필요한 가속을 피합니다. 그 외에는 60% 시작과 고온 보호를 사용합니다. 프리셋 재적용은 엔진을 초기화하지 않습니다. 출력·추세·타임스탬프·팬 정지 카운터를 유지합니다.
  • 실제 출력 최저값: 75°C에서 65%, 80°C에서 90%. 85°C는 즉시 100%. 온도/RPM 오류와 연속 정지 오류는 펌웨어 복귀를 우선합니다.
  • Silent는 40/30,55/30,65/38,75/65,85/100 곡선입니다. 기존 enum 숫자를 유지하기 위해 끝에 추가했으며 UI 순서는 별도 정의합니다.

팬 정지, 0dB 보증, 학습 AI, 자동 TDP/부스트 변경, 스피커 ANC는 구현하지 않습니다. 정책 온도는 제조사 정격이나 열 인증을 뜻하지 않습니다.

상태 전환과 장애

ControlSession은 하드웨어 생성기, 저장소, 로그 sink, 충돌 조회, 시계를 주입받습니다. 하드웨어 변경을 잠금으로 직렬화하고, 상태 조회는 불변 상태 스냅샷을 복사해 반환하여 드라이버 잠금을 기다리지 않습니다.

자동 복귀는 먼저 요청 모드를 Firmware로 바꿔 이후 수동 쓰기를 차단하고, EC 쓰기 검증 후 저장합니다. 저장만 실패하면 복귀 성공과 PersistenceWarning을 함께 반환합니다. 하드웨어가 없거나 복귀 검증에 실패하면 성공으로 보고하지 않습니다. 실패한 쓰기는 실제로 EC에 도달했을 수 있으므로 복귀 의무를 유지합니다.

수동 설정은 준비 상태·감시·최근 정상 샘플·충돌 여부를 확인하고 저장 성공 후 반영합니다. 접수와 적용 완료는 Pending 및 ActiveMode로 구별합니다. 수동 설정 저장 실패는 기존 요청을 유지합니다. Reset도 원자적 저장을 사용합니다.

센서 오류 시 온도/RPM/부하/전력을 비우고 마지막 SampleTime을 유지합니다. Time은 제어 주기 시각입니다. ControlState는 Unknown/Firmware/Manual이며, 요청 모드가 Firmware여도 검증이 실패하면 실제 상태는 Unknown입니다. LastProtection은 다음 정상 주기에도 유지하고 acknowledge로 지웁니다.

절전은 수동 해제·측정 무효화, 복귀는 기존 객체 폐기와 새 객체 생성 후 Firmware 시작입니다. 실패한 복귀 의무가 있을 때는 객체를 버리지 않습니다. retry는 같은 재초기화 경로를 사용합니다.

watchdog은 시작 확인 이벤트, heartbeat, 정상 종료, 절전 표시를 사용합니다. 시작 확인 후 프로세스 생존을 검사하고, 사라지면 수동 제어 중단 후 5초 간격으로 재실행합니다. heartbeat가 약 8초 끊기면 서비스 종료·mutex 획득·검증된 BIOS에서 자동 복귀를 시도합니다. SCM 재시작은 5/10/30초입니다. OS/커널 정지, watchdog 자체 정지, 외부 제어 경쟁은 잔여 한계입니다.

IPC

Named pipe PocketQuiet.v1의 확장 프로토콜 버전은 2입니다. 기존 명령은 유지하고 Silent/상태 필드를 추가합니다. 새 UI는 서비스 버전 0.2.0 이상을 확인합니다. 관리자/SYSTEM 허용, Network SID 거부, 동시 연결 1개입니다.

요청은 줄바꿈으로 끝나는 JSON, 최대 8192자, 깊이 16입니다. enum은 문자열만 허용합니다. 서버 읽기/쓰기 제한시간은 2.5초, UI는 대기열을 포함해 3.5초입니다. 드라이버 호출·동기 저장 자체의 중단은 watchdog이 담당하며 요청 접수 응답을 놓쳤을 때는 status로 실제 상태를 확인합니다.

명령: status, apply(Settings), reset, retry, acknowledge. 응답: Ok, Status, Error. 상태에는 Version, ProtocolVersion, Time, SampleTime, Device, Bios, Supported, Ready, WatchdogHealthy, Suspended, Pending, 측정값, Output, ActiveMode, ControlState, Reason, Error, PersistenceWarning, LastProtection, Settings가 있습니다.

저장·로그·개인정보

settings.json은 같은 디렉터리의 고유 임시 파일에 쓰고 flush 후 교체합니다. 읽기/검증 실패는 기본 설정과 보호 기록을 사용합니다. 시작 모드는 항상 Firmware입니다.

로그 작업은 별도 작업으로 분리하며 제어 스레드에서는 유한 큐에 넣습니다. 측정 큐 120개, 오류 큐 256개이며 포화 시 오래된 항목을 버립니다. CSV 일일 20MB·14일 보존, errors.log 약 2MB와 이전 파일 하나, watchdog.log 약 1MB와 이전 파일 하나입니다. 보존 정리는 매시간 실행합니다. 기록 누락이 있을 수 있으며 로그로 열 안전성을 증명하지 않습니다.

네트워크 분석·계정·마이크 녹음·소리 재생을 하지 않습니다. 오류에는 충돌 도구 이름이 들어갈 수 있습니다.

빌드·배포

소스 루트에서 scripts/build.ps1 또는 scripts/build.sh를 실행합니다. 프로젝트 잠금 파일로 restore하고 tests 실행 후 두 실행 프로젝트를 publish합니다. Python 의존성 설치 후 scripts/package.py로 HTML 문서, 전체 소스, 고정 SHA의 공식 PawnIO 설치 파일, notices/licenses, ZIP을 조립합니다.

배포 manifest에 파일 SHA-256, 버전, 소스 커밋과 dirty 여부를 기록합니다. 이는 파일 손상·혼합 검출용이며 게시자 서명을 대신하지 않습니다. 앱/서비스는 Authenticode 미서명입니다. 설치는 새 파일을 staging에 준비하고, 기존 서비스 중지와 watchdog 종료를 확인한 뒤 교체합니다. 검증 실패 시 이전 서비스 복원을 시도하고 이전 폴더는 보존합니다.

CI는 Windows 정책·상태 테스트, publish, 패키징을 수행합니다. 실제 열·소음·절전 검증은 CI에서 수행할 수 없습니다. 검증 기록은 VALIDATION.md에 구분합니다.

0.3.0 서명 준비와 저발열 전원

QuietPower.ps1은 기존 계획을 복제하고 원본 GUID 및 .pow 백업을 관리자 전용 데이터 폴더에 보관합니다. 전원 값은 AC/DC 모두 쓰기 후 확인하고 적용 실패 시 이전 활성 계획으로 복귀합니다. 반복 적용은 원본 백업을 덮어쓰지 않고, 복원 시 사용자가 선택한 별도 계획은 유지합니다. UI 데모는 이 스크립트를 실행하지 않습니다.

Sign-Package.ps1, Test-Signatures.ps1, package.py --finalize-signed가 서명→현재 파일 검증→manifest/ZIP 재생성을 처리합니다. SAC가 적용 중인 설치는 기존 서비스를 중지하기 전에 모든 실행 구성요소 서명을 확인합니다. 공인 서명 자격 증명이 아직 없어 실제 서명 성공 경로는 미검증입니다. 서명 절차와 외부 의존성을 참고하세요.
